Good to know

JSON from APIs and logs often arrives as one unreadable line. Formatting (pretty-printing) adds line breaks and indentation so the structure is visible at a glance — and a formatter doubles as a validator, pointing at the exact spot where broken JSON fails.

  • The most common JSON errors: trailing commas, single quotes, and unquoted keys — a validator finds them instantly.
  • Minify before sending JSON over the wire in production; pretty-print when debugging.
  • Never paste JSON containing real passwords or tokens into random websites — this formatter runs entirely in your browser, so data stays on your machine.

Frequently asked questions

What makes JSON invalid?

The most common causes are trailing commas, single quotes instead of double quotes, unquoted keys, and missing commas or brackets. The error message above points to the problem — modern browsers report the position of the first syntax error.

Does formatting change my data?

No. Format and Minify only change whitespace. The parsed value is identical — every key, value, number and string stays exactly the same, in the same order.

Why does my long number look different after formatting?

JSON numbers are read as double-precision floats, so integers beyond about 16 digits can lose precision when parsed. If you work with very long IDs, keep them as strings in quotes instead of raw numbers.

Is it safe to paste API keys or tokens here?

The tool runs entirely in your browser and stores nothing, so your data does not leave the device. Even so, good practice is to avoid pasting production secrets into any tool you do not fully control.
